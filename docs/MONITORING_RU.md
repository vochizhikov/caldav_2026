# Пользователи, ошибки и слепки БД

Админский модуль `bot/observability` создаёт две темы: **Пользователи** и **Ошибки**.
Администратор по умолчанию — **74529696**. Переписка, успешные запросы CalDAV и SQL
не журналируются; режимов подробного логирования и ежедневных архивов больше нет.

## Подключение

После установки этой версии и перезапуска `@testvochizhikovcaldavbot`:

1. Добавьте бота в закрытую группу с темами и дайте право управления темами.
2. От аккаунта 74529696 отправьте `/monitor_setup@testvochizhikovcaldavbot` в группе.
3. Бот создаст темы «Пользователи» и «Ошибки». Повтор команды не создаёт дубли.

Работает и прежнее имя `/logs_setup`. Для статуса: `/monitor_status` или `/logs_status`.
Эти команды доступны в личном чате администратора или подключённой группе;
привязка выполняется именно в группе. Анонимные команды от имени группы не принимаются.

Старая реализация с четырьмя темами заменена. Её `AUDIT_*` настройки больше не
используются. Выполните новую привязку через `/monitor_setup`; старые темы и файлы
в `data/audit` автоматически не удаляются и больше не пополняются.

## События пользователей

- **Новый пользователь:** первое обращение, после которого создана запись в `users`.
  Карточка содержит Telegram ID, имя, фамилию, @username и ссылку на профиль,
  язык, Premium и другие доступные флаги Telegram, внутренний ID БД, дату регистрации,
  часовой пояс, состояние подключения Яндекса и уведомлений. Необязательные поля
  показываются только в том объёме, который передал Telegram. Телефон и почта
  Telegram не появляются автоматически; логин Яндекса виден после подключения.
- **Ушёл:** Telegram прислал `my_chat_member` о блокировке бота в личном чате.
- **Вернулся:** разблокировка или новое обращение после ранее зафиксированной блокировки.
- **Яндекс подключён / отключён:** отдельные события после сохранения изменений.

Повторный `/start` не создаёт новый приход. Пользователи, уже находящиеся в БД
до включения модуля, при очередном обращении получают профиль без ложного уведомления
«новый пользователь». Повторы и устаревшие события состояния отбрасываются.

Удаление переписки или прекращение использования бота без блокировки не даёт
надёжного события ухода. Telegram сообщает о блокировке и разблокировке через
[my_chat_member](https://core.telegram.org/bots/api#update). Ошибка отправки 403 сама
по себе не считается подтверждённой блокировкой: возможны другие причины.

## Ошибки

В отдельную тему поступают ошибки обработчиков, CalDAV, исходящих запросов Telegram
и прикладные записи уровня ERROR/CRITICAL. В сообщении есть время, источник,
класс ошибки, безопасный код/название операции и расположение в коде, если доступно.
Для действий пользователя добавляется Telegram ID; у фоновой ошибки он может
отсутствовать. Внутренний ID из журнала синхронизации подписан отдельно.

Тексты исключений, пользовательских сообщений, тела HTTP, SQL-параметры, локальные
переменные и секреты в тему не передаются. Для диагностики конкретных данных
используйте админские слепки. Первая ошибка отправляется при ближайшей обработке
очереди; одинаковые повторы объединяются в счётчик и последующую сводку не чаще
одного раза в пять минут. Отдельные источники одной ошибки могут дать две записи.

Очередь проверяется примерно раз в 3 секунды. Отправки ограничены по частоте и
повторяются после временных сбоев. События и счётчики сохраняются при перезапуске.
Сбой одной темы не блокирует другую. Доставка допускает повтор, если Telegram принял
сообщение, а бот завершился до сохранения подтверждения.

Модуль не является внешним монитором доступности. Падение процесса, ошибка до его
инициализации или потеря доступа к Telegram могут помешать немедленному уведомлению.
Обычные технические сообщения в консоли/Docker продолжают работать.

## Слепки: только по команде в личном чате администратора

| Команда | Результат |
|---|---|
| `/db_user 123456789` | JSON по **Telegram ID**: профиль и настройки, календари, встречи и экземпляры повторяющихся встреч |
| `/db_user id:42` | Тот же слепок по **внутреннему ID** строки `users` |
| `/db_users` | JSON всей таблицы `users` |
| `/db_stats` | Количество пользователей, календарей, событий, экземпляров событий и уведомлений |

В JSON исключён `encrypted_password`, вместо него есть признак `connected`.
Токен бота и ключи шифрования не экспортируются. Для конкретного пользователя
добавляются известные модулю сведения Telegram; `users` содержит именно данные
основной таблицы, в которой имён и username нет. Переписка не входит в слепки.

Выгрузки читают согласованное состояние БД, не изменяя её. Поддерживаются SQLite
и PostgreSQL. JSON содержит версию формата, время создания и счётчики строк.
Размер ограничен 45 МиБ; слишком большой экспорт завершается с понятным сообщением
и удалением частичного файла. Полная копия файла базы командой не предоставляется.

Команды выгрузки в группе не выполняются — обратитесь к боту лично. Временный файл
удаляется после успешной или неуспешной отправки; слепок можно запросить повторно.
При аварийном завершении процесса временный файл может остаться в каталоге `snapshots`;
это не очередь автоматической отправки.

## Хранение и настройки

Монитор хранит профили, привязку тем, очередь событий и счётчики ошибок в отдельной
`data/monitoring/monitor.sqlite3`. Рабочая схема календарной БД не меняется.
События пользователей удаляются из очереди после отправки; метаданные профилей
остаются для распознавания повторных приходов/уходов. Уже отправленные старые группы
ошибок очищаются при поступлении новых типов ошибок.

| Переменная | Значение по умолчанию |
|---|---|
| `MONITOR_ENABLED` | `true` |
| `MONITOR_ADMIN_IDS` | `[74529696]` |
| `MONITOR_DIRECTORY` | `data/monitoring` |
| `MONITOR_ERROR_REPEAT_SECONDS` | `300` |
| `MONITOR_MAX_PENDING` | `10000` событий пользователей и до 10000 групп ошибок |

При переполнении новые события пропускаются, счётчик доступен в `/monitor_status`,
а предупреждение пишется в технический журнал. Недоставленные события не удаляются
для освобождения места. Размер профилей также зависит от числа пользователей.

Docker Compose задаёт каталог `/data/monitoring` на постоянном томе `./data:/data`.
Настройки берутся из `.env`/переменных окружения, в контейнере — из `.env.docker`.
Один экземпляр бота должен владеть каталогом и токеном.

## Отключение и удаление

`MONITOR_ENABLED=false` и перезапуск отключают весь модуль, включая админские
команды слепков. Уже отправленные сообщения и локальные файлы сохраняются.

Для удаления кода уберите из `bot/bot.py` импорт `install_monitor`, блок установки,
переменную `monitor` и вызов `monitor.close()`. Затем можно удалить `bot/observability`,
его тесты `tests/test_monitor*.py` (тест корректного завершения можно оставить,
адаптировав заглушку), этот документ, ссылку в README и настройки `MONITOR_*`.
Основные обработчики, модели, репозитории и CalDAV-клиент не зависят от модуля.
Миграций и новых зависимостей нет. Старые данные удаляются отдельно по решению владельца.
